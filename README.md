# 新能源维保工时透视

`hxwl-solo2611-11` · 透视汇总与钻取

计划员从周计划取预算工时和计划作业量，班组从维保工单回填实耗和完成量。班前会按设备类型交叉核对班次或承包商，确定哪些工单该补分类、哪些检修包该重估工时。

## 模拟客户与工作流

栖原新能源·海岬检修车间（模拟，46 名检修员，覆盖 2 座风场和 1 座光储站）

- 班组把每张工单的超支率直接平均，零预算应急单和大检修包经常被算错。
- 承包商和夜班归属靠 Excel 补写，透视筛掉空白后常与底账差几个人时。
- 统计表只剩设备小计，主管还要重开原始工单才能区分作业增量和单耗变化。

检修主管根据点检清单和签工记录复核超线组合。计划组区分追加作业量和单耗影响，运维台账组按工单补齐缺失分类后复跑。

## 业务模块

- 维保工时台账
- 工时透视设置
- 预算偏差与对账
- 班组分发收件箱

## 计算口径

每行对应一张工单，工时报到百分之一人时。净差为实耗减预算，加权偏差率为净差除以预算总量。零预算组保留实耗和净差，偏差率留空。

按工单用原预算单耗计算作业量影响，四舍五入到 0.01 人时。剩余净差归入单耗及其他影响。零预算工单的净差全部归入无预算用工。三项之和等于净差。作业点数只在同一工单内比较。

按当前透视口径分别列出单列缺失和两列同时缺失的工单，全部纳入合计。组号可追溯到工单号、日期与资产，追溯范围只影响工单明细。

样例输入为 `海岬车间_2026-11-16至21_维保工时.csv`，见 `backend/demo/sample.csv`。相同输入与参数复现相同结果。格式错误在导入时提示，样本量或业务约束不满足时在后台运行结果中提示。

## 一班如何使用

1. 2026 年 11 月 23 日 07:45，计划员把 11 月 16–21 日的 36 张工单整理为海岬车间_2026-11-16至21_维保工时.csv。
2. 08:10，导入台账后用设备类型与班次跑透视，净超支复核线设为 12 人时。
3. 08:25，主管复制风机夜班的组号 G0010 重跑追溯，核对 HJ-261118-016 和资产 WT-07。该单预算 24 人时，实耗 37.5 人时。
4. 08:40，按承包商重跑，检查澄屿电维与其他队伍的工时差，并回看 HJ-261120-029 的无预算应急用工。
5. 09:00，台账组从分类对账定位 HJ-261121-035，该单缺设备类型和班次，按原资产编号 CB-09 查填报记录。
6. 09:20，主管用原派工单复核待办，计划组把追加作业点和原预算单耗拆开登记。
7. 09:45，完成复核并把含对账表和工单明细的结果分发给海岬检修主管组和海岬工时计划组。

## 启动与本地开发

```sh
cp .env.example .env
docker compose up -d --build --wait
docker compose exec -T backend python -m scripts.seed_demo
```

停止本地服务可执行 `docker compose down`。仅清理演示数据时使用 `docker compose down -v --remove-orphans`。

浏览器 `http://127.0.0.1:18320`，API `http://127.0.0.1:19320`，数据库宿主端口 `17820`。

前端由 Nginx 提供原生 HTML/CSS/JS，并将 `/api/` 转发给 FastAPI。Python 3.11 Worker 使用 Redis 唤醒和 PostgreSQL 16 运行租约，生成的 CSV 由命名卷共享。可编辑 `frontend/src/pages`、`backend/src/services/analysis.py` 和 `backend/demo` 后执行 `docker compose up -d --build --wait`。Compose 默认映射到本机回环地址。更改 `.env` 可配置端口、数据库密码、JWT 密钥以及 `SEED_DEMO` 种子开关。演示凭据适用于本机模拟数据。

| 角色 | 账号 | 密码 | 工作内容 |
|---|---|---|---|
| 主管 | admin | admin-demo-2611 | 查看审计，复核运行，安排与停用分发计划 |
| 分析员 | analyst | analyst-demo-2611 | 导入 CSV、运行计算、下载结果 |
| 只读 | viewer | viewer-demo-2611 | 查看数据、结果和投递回执，下载 CSV |

角色、运行状态和复核状态在 `backend/src/constants/enums.py` 与 `frontend/src/constants/enums.js` 同步定义。角色参与登录、路由授权和工具栏控制。运行状态在 Worker、任务接口和结果页使用。复核状态在运行模型、复核接口和交付页使用。

核心实体为 CSV 数据批次、分析运行、分发计划及其投递回执。业务参数与真实模拟数据位于 `backend/demo/`。后端分为 routes、controllers、services、models、schemas 和中间件，前端分为 api、store、组件和业务页面。授权模式见 [LICENSE](LICENSE)。
